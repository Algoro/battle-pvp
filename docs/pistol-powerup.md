# Приз «Пистолет» и супер-оружие (Railgun)

Фича `pistol` (включается `features: ["pistol"]`): приз «пистолет» выпадает и подбирается,
4-я звезда выдаёт тот же эффект. Эффект луча исполняет JS-рантайм (`features/railgun.ts`),
правила получения — ROM-патчем `pistol`. База `pvp` без фич — `94cb0636`, с пистолетом —
`d370108f`.

## 1. Цель

Сделать выпадающим/подбираемым **приз «Пистолет»** (сейчас в ROM есть его спрайт, но
приз не используется) и дать подобравшему танку **мощное оружие**: выстрел, который
**за один выстрел уничтожает любые препятствия и противников по всей линии через весь
экран**. Реализация — в рамках принципов проекта: ROM неизменяем, правила живут в ROM,
детерминизм и rollback сохраняются, патч применяется in-memory и входит в fingerprint.

## 2. Что уже есть в ROM (проверено по дизассемблеру)

### 2.1. Призы («bonus»)
- Идентификатор и позиция: `ram_bonus_id` `$88` (0xFF — приза нет), `ram_bonus_pos_X/Y`
  `$86/$87`, таймер `ram_bonus_timer` `$62`.
- Отрисовка `sub_E23B_display_bonus_on_screen` (`$E23B`): тайл = `0x81 + bonus_id*4`,
  рисуется 2 спрайтами 8×16 (2×2 тайла). Для `id=6` это тайлы **`0x99–0x9C`** —
  в CHR действительно лежит отдельная графика (пистолет).
- Таблица выпадения `tbl_E8FA_bonus` (`$E8FA`, 8 байт): `00 01 02 03 04 05 04 03`
  (helmet/clock/shovel/star/grenade/tank/grenade/star). **`6` не выпадает никогда.**
- Таблица эффектов `tbl_E9E2_bonus_pickup_handler` (`$E9E2`, слова): запись `id=6`
  (`$E9EE`) указывает на `ofs_bonus_EA48_06_RTS` (`$EA48`) — **пустой `RTS`**
  (в дизассемблере помечен `; pistol`).
- Подбор `sub_E972_try_to_pick_up_bonus` (`$E972`): проверяет только танки `0..1`
  (`con_max_players = 1`, т.е. DEF-игроки). ATT/враги (2..7) призы не подбирают.
- Спавн `sub_E8BE_spawn_bonus` (`$E8BE`) вызывается из `sub_E70C` (`$E7D7`), когда
  убит танк с `ram_tank_type & 0x04` (носитель приза).
- Спавн задаётся RNG: `sub_D44D_generate_random_number`. Патч `pvp` уже сделал его
  детерминированным (`$D45A`), т.е. последовательность призов синхронна у клиентов.

### 2.2. Пули
- Слоты `0..9`; массивы: `ram_bullet_pos_X` `$B8`, `pos_Y` `$C2`, `status` `$CC`,
  `property` `$D6` (+ 2-е пули игроков на `+8`: `$C0/$CA/$D4/$DE`).
  Игроки — слоты 0,1; враги — 2..7.
- `sub_E08C_bullets` (`$E08C`, байты `B5 CC D0`, продолжение `$E090` `CPX #$02`) —
  создание пули: выставляет `status = 0x40 | dir`, позицию, `property`.
- `property`: `0` обычная; `1` «мощная» (танк 200 очков); `3` — 3 звезды игрока
  (проверка `property & 0x02` → уничтожает сталь).
- Движение `sub_E604_bullets_movement` (`$E604`); коллизия с тайлами
  `sub_E69A` (`$E69A`, вход из `sub_E693`); коллизия с танками
  `sub_E70C` (`$E70C`); пуля-против-пули `sub_E910` (`$E910`).
- Коды блоков (`con_block_type = 0`): тайл `>= 0x12` — пусто; `0x08` — штаб (проигрыш);
  `0x11` — пуля гаснет (неразрушаемое); `0x10` — сталь (разрушается при `property&2`);
  прочие — кирпич. Разрушение тайла с обновлением nametable —
  `sub_D784_write_tile_to_buffer` (`A = новый тайл`).

### 2.3. Огонь
- Игроки DEF: `sub_E122` (`$E122`), вызов создания пули — `$E15A` (`20 8C E0`).
- ATT (человек/сеть): `sub_E162` (`$E162`); пvp-хук огня — `$E171`; вызов создания
  пули — `$E178`. Хук возвращает `A=0` → выстрел.
- Обе ветки в итоге вызывают **`sub_E08C`** — это единая точка для «супер-выстрела».

### 2.4. Инфраструктура патчей
- `emulator-core/patching/`: дескрипторы `routines` (символы, `at`/first-fit, токены
  `jmpT/jsrT/absT/selfJmpT`) и `writes` (хук по адресу, `len`, `expect`, байты).
  Линкер размещает только в объявленных `free`-зонах, заполненных `0xFF`, и проверяет
  атомарность/перекрытия. `applyPatchSet(rom, "pvp")`; `composeSets`; `registry.ts`.
- Свободные (`0xFF`) зоны PRG: **`$EF75–$EFFF`** (занята патчем `pvp`),
  **`$FF50–$FFF9` (170 байт)**, `$D3DD–$D3FF` (35), `$FD46–$FD4F` (10).
- Потребители: `scripts/prepare.mjs` (собирает `rom/disasm/_battle_city.nes`,
  константа `PRG_FNV = 94cb0636`), `emulator-core/tests/patching.test.ts`
  (fingerprint `94cb0636`), `qa/tests/asm-patch.test.ts`,
  `emulator-core/tests/golden-replay.test.ts` (`GOLDEN_HASH = 34e8ff73`),
  `qa/golden-state.ts`, `emulator-core/tests/no-magic-addresses.test.ts` (regex адресов),
  `emulator-core/rom-contract.ts` (единый источник RAM/ROM).
- JS-ядро `PvPNes` (`emulator-core/pvp.ts`): `loadROM` → `applyPatchSet`;
  `stepFrame` = `_readInputs` → ИИ → `_applyHumanPreFrame` → `frame()` →
  `_applyHumanPostFrame` → `_unstuckTanks`; `saveState/loadState` кодируют **всю RAM
  `0x0000–0x07FF`**. `sim/*` — тест-онли JS-модель. Lookahead-ИИ использует
  `EmulatorPredictor` (реальный эмулятор, `ai/rollforward.ts`), т.е. патч учитывается.

## 3. Дизайн фичи

### 3.1. Спецификация
- Пистолет — приз `id=6`, выпадает на поле как остальные (позиция/RNG — как раньше,
  частота — как у обычных призов; при желании регулируется).
- Доступен **только DEF-игрокам** (танки 0,1) — как все призы сейчас; ATT/ИИ не
  подбирают. `sub_E972` не расширяем.
- **Второй источник супер-оружия — 4-я звезда:** апгрейд танка в оригинале
  ограничен `0x60` (3 звезды): `ofs_bonus_EA07_03_star` при `ram_tank_upgrade == 0x60`
  делает `RTS`. Теперь подбор звезды на максимуме (т.е. 4-й) выдаёт **тот же эффект,
  что и пистолет** (см. §3.3, шаг 6). Оба пути ведут в общую рутину выдачи.
- Подобравший игрок получает **N супер-выстрелов** (по умолчанию **N=3**; хранится в
  RAM), затем стрельба возвращается к обычной. Действует до исчерпания боезапаса или
  до смерти танка (что раньше). Если уже есть оружие — повторный подбор
  (пистолет/4-я звезда) **пополняет боезапас до N** и не суммируется.
- Супер-выстрел — **hitscan (луч)**: в кадр выстрела мгновенно «прожигает» линию от
  танка до края экрана в направлении взгляда:
  - уничтожает **любые** тайлы (кирпич и сталь), пишет `0` в поле и обновляет
    nametable через `sub_D784_write_tile_to_buffer`;
  - уничтожает **живых танков в полосе**, включая **союзный DEF-танк** (friendly fire);
  - **разрушает штаб (базу), включая свой**, и запускает штатную последовательность
    поражения (как обычная пуля: `ram_game_over_flag = 0x27`, `sub_CC08_draw_destroyed_eagle`,
    SFX) — согласовано;
  - убирает вражеские пули в полосе;
  - не выходит за границы поля (важно: иначе байтовый X/Y «завернётся» и танк телепорт);
  - визуал: **луч + серия взрывов** вдоль линии на несколько кадров, SFX.
- Почему hitscan, а не «летящая пробивающая пуля»: в ROM движение пули — по байтовым
  координатам без проверки края; пробивающая пуля, снося границу, «завернётся» через
  `x=255→0`. Hitscan решает «через весь экран» одним проходом, проще, детерминирован и
  не требует правок четырёх подпрограмм коллизий. Визуально можно показать луч/серию
  взрывов (опция).

### 3.2. Данные (RAM)
- Так как участвуют только DEF (танки 0,1), достаточно **2–4 новых байт**: 1 байт на
  игрока (бит «владеет» + счётчик выстрелов) или 2 байта флага + 2 байта боезапаса.
  Точный свободный адрес —
  **подтвердить проверкой**: кандидаты — хвост PvP-зоны (`$01EE–$01FF`) или
  свободный участок (`$0111–$017E`), с проверкой, что туда не пишет `ram_ppu_buffer`
  (`$0180`) и индексируемые массивы. Зарегистрировать в `rom-contract.ts`,
  `no-magic-addresses` и контрактном тесте; покрыть `state-codec` (rollback/saveState).

### 3.3. Исходный дизайн ROM-пути (не реализован; см. §5)
Новый модуль `emulator-core/patching/patches/pistol.ts`, собирается как
`composeSets(baseNrom, pvp, pistol)` и регистрируется под именем `pvp`
(чтобы фронт/тесты ничего не меняли; меняется только fingerprint). Содержимое:

1. **Выпадение.** `writes`: `$E900` (запись `tbl_E8FA_bonus`, индекс 6) ожидаемо `04`
   → `06` (или индекс 7 `03→06`; частота — см. §3.1). Альтернатива: не трогать таблицу, а
   выдавать пистолет по условию (например, после N убийств) — сложнее, отдельная фаза.
2. **Подбор.** `writes`: слово `$E9EE` (`48 EA`) → `absT("sub_pistol_pickup")`.
   Новая рутина `sub_pistol_pickup` (в `$FF50+`): `X` = индекс игрока; установить флаг
   (и/или боезапас), при желании поднять апгрейд до максимума, проиграть SFX, `RTS`.
   Опционально расширить `sub_E972` на ATT (сейчас только `0..1`).
3. **Хук создания пули.** `writes`: `$E08C`, `len=3`, `expect = B5 CC D0` →
   `jmp("sub_bullets_pistol_hook")`. Хук:
   - `LDA ram_bullet_status,X; BNE rts` (занятый слот — как оригинал);
   - если у танка `X` есть пистолет → `JMP sub_railgun`;
   - иначе `JMP $E090` (продолжить оригинал после 3 перезаписанных байт);
   - `rts: RTS`.
   Единый хук покрывает и DEF (`sub_E122`), и ATT (`sub_E162`) — обе ветки вызывают
   `sub_E08C`.
4. **`sub_railgun`** (новая рутина, `$FF50+`), вход `X` = индекс танка (0/1):
   - направление из `ram_tank_flags,X & 3`; стартовая точка — позиция танка;
   - пошаговый проход по клеткам вдоль луча (32 тайла):
     - тайл поля: если не пусто → `sub_D784_write_tile_to_buffer(A=0)`;
     - если тайл — **штаб** (`0x08`): уничтожить и запустить штатное поражение
       (`ram_game_over_flag=0x27`, `sub_CC08_draw_destroyed_eagle`, SFX) — работает и
       для своей базы (согласовано);
     - танки 0..7 (включая союзный DEF) в клетке → взрыв
       (`ram_tank_flags=0x73`, `ram_tank_type=0`, SFX);
     - пули в клетке → обнулить статус;
   - останов на границе поля; списание боезапаса/снятие флага при 0; SFX; `RTS`.
5. **Визуал (согласовано).** Луч + серия взрывов вдоль линии: 3–6 вызовов
   `sub_DEE2_draw_bullet_explosion` по ходу луча (или новый статус пули-спрайта через
   диспетчер `$E4D8/$E4E2`). HUD-иконка пистолета рядом с жизнями — опционально
   (`sub_C830_draw_Ip_IIp_icons`).
6. **4-я звезда.** `writes`: `$EA07`, `len=3`, `expect = BD 01 01`
   (`LDA ram_tank_upgrade,X`) → `jmp("sub_star_pickup")`. Новая рутина `sub_star_pickup`
   (`X` = игрок) повторяет оригинал и при исчерпании:
   - если апгрейд `< 0x60` → как раньше: `upgrade += 0x20`, `tank_type = upgrade`, `RTS`;
   - если `== 0x60` → `JMP sub_grant_super_weapon` (общая рутина с пистолетом).
   `sub_grant_super_weapon` устанавливает флаг владения и `ammo = N` (пополнение).
7. **Сброс при смерти.** Поражение DEF-танка обнуляет `ram_tank_upgrade,X` и
   `ram_tank_type,X` (`sub_E70C` `$E76A/$E76D`). Туда же добавить сброс супер-оружия:
   `writes` на `$E76A` (`expect = 9D 01 01`) → `jsr("sub_clear_super_weapon")`, где
   рутина обнуляет `ram_tank_upgrade,X`, `ram_pistol,X` и `ram_ammo,X`, а на выходе
   **оставляет `A=0`** (перед хуком идёт `LDA #$00`, а сразу после — `STA ram_tank_type,X`
   на `$E76D`, использующий тот же `A`).
   Резервный путь (если найдётся иное поражение) — обнулять флаг по `flag == 0` в
   `_defRespawn`; но предпочтителен ROM-хук.

## 4. Тестирование
- **Headless (emulator-core/qa)**: подбор приза 6 (`spawnBonus(6,x,y)` + подъезд танка);
  подбор **4-й звезды** (апгрейд до `0x60`, затем ещё звезда) выдаёт оружие, а 1–3-я
  звёзды — нет; супер-выстрел уничтожает кирпич/сталь (поле → 0, nametable-буфер
  обновлён); уничтожает врага и союзника в линии; попадание в штаб запускает поражение;
  не выходит за границы и не «заворачивает» координаты; не-супер выстрел не изменился
  (регрессия); боезапас/пополнение до N/снятие флага; смерть танка сбрасывает
  флаг/боезапас; SFX не влияет на хэш.
- **Детерминизм/rollback**: save/load и периодический save/load в момент супер-выстрела
  эквивалентны непрерывному прогону.
- **Патчинг**: `node scripts/extract-patches.mjs --check` воспроизводит собранный ROM;
  fingerprint стабилен; guard `jsnes-pristine` не затронут.
- **Golden**: осознанно обновить `GOLDEN_HASH` и `qa/golden/*` (изменение таблицы
  выпадения приза меняет состояние).
- **Изоляция sim**: убедиться, что pistol-сценарии не попадают в сверки `emu` vs `sim`
  (или явно исключить/задокументировать).
- **E2E (opt.)**: лобби → старт → супер-выстрел виден/синхронен у обоих клиентов.

## 5. Фактическая реализация

- ROM-патч `emulator-core/patching/patches/pistol.ts` (набор `pvp = base + pvp + pistol`,
  fingerprint `d370108f`): выпадение id 6, подбор, 4-я звезда, сброс при смерти.
- RAM `ram_pistol` `$01EE`, `ram_pistol_ammo` `$01F0` (`rom-contract.ts`).
- Эффект луча — JS-рантайм `emulator-core/features/railgun.ts` (`fireRailgun`/`renderRailgunFx`), вызывается из `features/pistol.ts`:
  hitscan по клеткам, уничтожение **любых препятствий и ландшафта — кирпич, сталь,
  вода, лёд, кусты** (кроме дороги и штаба), танков (включая союзника),
  пуль, базы; N=3; **ширина луча = `2*PISTOL_BEAM_HALF+1`** тайлов
  (`domain.ts`, сейчас 3 тайла, можно менять одной константой); **визуал — взрыв
  (анимация как у танка) на каждой разрушенной клетке**: JS-очередь `ctx.state.beamFx` + `renderRailgunFx` рисует 8×16-пары тайлов `0xF1/0xF5/0xF9` в свободные (внеэкранные)
  OAM-спрайты движка — чистая визуализация, не пишет `cpu.mem` (hash/сеть не затронуты);
  SFX. Состояние разрушения — в RAM → `saveState`/rollback работают.
- **Стартовая опция**: `setStartPistol(true)` (в `StartupInjector` + `PvPNes` + `EmulatorDriver`)
  выдаёт DEF максимум звёзд (`0x60`) и пистолет на старте. Проброс: UI (`StarsSelect`
  кнопка «4★🔫» → `LobbyBrowser`/`CreateRoomDialog`/`LobbyRoom`) → настройки лобби
  `defPistol` (`domain/lobby.ts`, `match-lifecycle.ts`, `relay`/`server`) → `match.start`
  → `MatchController` (`startSolo`/`startOnline`) → `setStartPistol`.
- Тесты: `emulator-core/tests/pistol.test.ts` (13), `backend/tests/lobby.test.ts`
  (normalizeSettings.defPistol), обновлены fingerprint (`patching.test.ts`,
  `prepare.mjs`) и golden (`GOLDEN_HASH = 34e8ff73` в `tests/golden-replay.test.ts`).
- Причина fallback: railgun в ASM не помещается целиком в непрерывную свободную зону ROM
  (`$FF50–$FFF9` = 170 Б; один routine не может занимать две зоны), а правила получения
  остались в ROM. Если понадобится полный ROM-вариант — писать компактнее/расширять зоны.
