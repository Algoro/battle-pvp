# Agent-Patcher — реализация ASM-патчей

Дата: 2026-08-23
Вход: `reports/agent-asm-architect.md` (ТЗ), `reports/agent-rng-audit.md`.
Статус: реализованы и проверены P1 + P2 (главный хук). Остальные патчи (P2-доп.,
P3, P4, P5) — пошагово далее, та же методология.

## Методология (критично)
- Правки вносятся в `./rom/disasm/bank_FF.asm` / `bank_ram.inc` / `bank_val.inc`.
  `preparations.lua` снимает дамп-префикс регуляркой и собирает `copy_bank_*.asm`
  через `ca65 -U`. Новые строки можно писать без дамп-префикса (регэксп их не трогает).
- **Ключевое ограничение: банк FF заполнен на 100% и это ОДИН сегмент.** Любое
  изменение РАЗМЕРА кода сдвигает адреса всего последующего кода → десятки тысяч
  байт в byte-diff и ломает regression-сверку «неизменённых зон».
- **Правило: каждый патч — СТРОГО РАВНОГО РАЗМЕРА с заменяемым кодом.** Если нужно
  вставить новую логику — в заменяемое место кладём `JMP`/`JSR` (3 байта) + `NOP`-пады
  до исходной длины, а саму логику размещаем в свободной зоне («bzk garbage» EF75-EFFF).
  Итог: byte-diff показывает ТОЛЬКО изменённые байты, адреса не сдвигаются.

## P1. RAM-метки сетевой зоны (bank_ram.inc)
Добавлены (блок $01DB-$01FF, подтверждённо свободный):
- `ram_net_enemy_dir` = $01DB (6 б, направление ATT-танка 2..7: 0=Up 1=Left 2=Down 3=Right, FF=нет)
- `ram_net_enemy_fire` = $01E1 (6 б, edge выстрела)
- `ram_net_enemy_respawn` = $01E7 (6 б, edge респавна)
- `ram_net_match_state` = $01ED (1 б)
Заполняются эмулятором каждый кадр. Регистры RNG ($0F,$10) в save state.

## P2. Enemy AI → сетевой ввод (главный хук, реализован)
Точка `sub_DDA2` (CPU DDA2), ветка `bra_DDD4_enemy` (ROM 0x1DE4) — выбор направления
вражеского танка на перекрёстке (было: `JSR sub_D44D` RNG AND#$01 + таблица).
- **Стало:** `JMP sub_net_enemy_dir` + 4×NOP (7 байт, размер не меняется).
- **Новая подпрограмма `sub_net_enemy_dir`** (ROM 0x2F85, CPU EF75, в «bzk garbage»):
  ```
  TXA; SEC; SBC #$02; TAY           ; индекс 0..5
  LDA ram_net_enemy_dir,Y           ; сетевой ввод танка X
  BMI keep                          ; FF (bit7) = нет ввода
  ORA #con_tank_flag_A0             ; A0|dir
  RTS
  keep: LDA ram_tank_flags,X; RTS   ; продолжить текущее направление
  ```
  Возвращает флаг направления, вызывающий код (`sub_DDA2` → caller) пишет его в
  `ram_tank_flags,X`.
- Направление: 0=Up,1=Left,2=Down,3=Right (совпадает с `sub_E451`/`tbl_E470`).
- RNG `sub_D44D` НЕ тронут (алгоритм сохранён; точка вызова в DDD4 заменена, что по
  RNG-audit безопасно и не влияет на детерминизм при равных входах).

## Верификация
- Пересборка: `./rom/disasm/_battle_city.nes`, 24592 байт, `Free bytes: 0x0000`
  (банк снова заполнен, без сдвига адресов).
- **Byte-diff против базы (e1061c92): ровно 23 байта** — только намеренные изменения:
  - ROM `0x1DE4-0x1DEA` (7 б): `JMP $EF75` + NOP×4
  - ROM `0x2F85-0x2F94` (16 б): `sub_net_enemy_dir`
- Побайтово подтверждено: `4C 75 EF EA EA EA EA` и `8A 38 E9 02 A8 B9 DB 01 30 03 09 A0 60 B5 A0 60`.
- Regression-тест: `./rom/tests/test-p2-ai-netinput.sh` — PASS (размер, ветка, подпрограмма).

## П2-доп. (добавлено при Agent-QA)
Функциональный тест выявил: одного хука `sub_DDA2` НЕДОСТАТОЧНО — базовый враг в
`ofs_000_DC7C_A0` вызывает `sub_DE72` (RNG-точка DE84), который перезаписывает
направление AI-целеуказанием, «затирая» сетевой ввод. Добавлен второй хук:
- `sub_DE72` DE84: `JSR RNG; AND #$03` → `JMP sub_net_enemy_dir_store; NOP; NOP`
  (5 байт, размер не меняется).
- Новая подпрограмма `sub_net_enemy_dir_store` (ROM 0x2F9x): читает
  `ram_net_enemy_dir[X-2]`, пишет `A0|dir` в `ram_tank_flags,X` и RTS.
- Byte-diff после доп.: 44 байта в 3 чистых зонах (0x1DE4 sub_DDA2, 0x1E94 sub_DE72,
  0x2F85+ обе подпрограммы). Банк снова заполнен (0x0000).
- Функционально подтверждено (headless-эмуляция): враг в поле движется по
  `ram_net_enemy_dir` (влево/вправо), без ввода — AI.

## Риски
- «bzk garbage» EF75-EFFF = 139 байт. На P2 израсходовано 16. Бюджет на P3v2/P4/P5
  ограничен (~123 б); при нехватке — сокращать «bzk optimize»-дубли или debug-режим C755.
- Функциональная проверка поведения — после Agent-EmulatorCore (Agent-QA).
