# Session Report — Исправление «торможения» и «проникновения в стены» атакующего танка

> Дата: 2026-08-24 (обновлено 2026-08-26 после финального фикса).
> Цель: позволить продолжить работу в новой сессии агента. Это снапшот состояния,
> НЕ документация архитектуры (см. `docs/architecture.md`).

## 1. Проблема

Пользователь сообщил (соло-режим «Атакующие», где танк игрока управляется JS):

1. **Начальный репорт**: «в соло режиме атакующих — если происходит какая-то
   коллизия, то движение танка сильно замедляется». Танк двигался рывками у
   кирпичей, в отличие от остальных (DEF) танков, которые ведут себя по ASM.
2. **Уточнение после первой попытки фикса**: «теперь я могу частично проникать в
   препятствия (и даже частично в стены). И когда я частично в них проникаю, моё
   движение замедляется».

## 2. Итоговая причина

Корень проблемы — **рассинхрон коллизии JS-оверрайда и ASM**.

Движение человеческого танка задаётся JS: `stepTank` (`emulator-core/pvp.js:192`)
вычисляет целевую позицию и пишет её в RAM `0x90/0x98` **после** кадра ASM.
Если JS-коллизия (`canLead`) не совпадает с коллизией ASM, возникает конфликт:

- **Слишком строгий JS** (проверял всю переднюю кромку, 13px) → танк «цеплялся»
  за боковые кирпичи и тормозил.
- **Слишком мягкий JS** (проверял только центр кромки) → JS ставил танк **внутрь**
  стены/препятствия (частичное проникновение), а ASM на следующем кадре считал
  танк заблокированным и «боролся» → движение замедлялось.

## 3. Правильное решение

Сделать JS-коллизию **в точности равной коллизии ASM** (`bank_FF sub_DC97`).
Тогда JS-оверрайд никогда не расходится с ASM: нет ни «цепляния», ни
«проникновения», ни замедления. Человеческий танк ведёт себя как остальные.

Реализация: `emulator-core/tank-driver.js`, `canLead` (целевой центр `(x+dx, y+dy)`)
повторяет ASM-проверку 2 углов передней кромки:

```
cx = x+dx, cy = y+dy          // целевой центр (ram_0056/57)
ox = dx*8, oy = dy*8          // смещения (ram_0058/59)
clamp(v,c) = v >= c ? v-1 : v // sub_DD6E/sub_DD76
Точка A: (clamp(cx+ox+oy, cx), clamp(cy+ox+oy, cy))
Точка B: (clamp(cx+ox-oy, cx), clamp(cy+oy-ox, cy))
блок, если любая из 2 ячеек непроходима
```

- Это **2 точки** (не весь корпус) → танк не «цепляется» за боковые кирпичи и
  плавно скользит вдоль стен.
- Это **2 угла** (не только центр) → танк не проникает в стены (JS не ставит его
  туда, куда ASM не пустил бы).
- `stepTank` вызывает `canLead(pos.x, pos.y, dir)` (текущая позиция), а не уже
  сдвинутую `(nx,ny)` — чтобы не задваивать `dx` (важно! первая версия порта
  задваивала шаг, это ловилось отладкой).

Границы поля: за пределами поля коллизия считается блоком (`cellPassable`),
что зеркалит сплошную кайму буфера `$0400`.

## 4. Постоянные контекста (не менялись)

- `TILE = 8`, `FIELD = 32`, `TANK = 13`, `HALF = 6`.
- RAM-позиция танка `(x,y)` — **центр** танка; спрайт рендерится в OAM `x-8, y-1`.
- Направления: `0=Up, 1=Left, 2=Down, 3=Right` (совпадает с `tbl_E46C/E470`).
- `DX=[0,-1,0,1]`, `DY=[-1,0,1,0]` — совпадают с E46C (X) и E470 (Y).
- Проходимость `runtimePassable` зеркалит ASM: проходимы `0x00` и `0x20..0x7F`;
  блокируют `0x01..0x1F` и `0x80..0xFF`. Вода `0x0f/0x15` для танков непроходима.
- ASM-коллизия использует эффективный бокс **±8 (16px)** — на 2px шире визуального
  корпуса 13px. Из-за этого танк останавливается в ~2px от стены и, вплотную к
  стене, не может двигаться вдоль неё (угол корпуса упирается в соседний тайл).
  Это поведение ВСЕХ танков игры (не баг человеческого).

## 8. Ход диагностики (для будущей сессии — что уже исключено)

- **Полно-кромочный `canLead`** (проверка всего корпуса спереди) — вызывал
  «цепляние» у кирпичей. Заменён.
- **Центр-кромочный `canLead`** (1 точка) — вызывал «проникновение в стены» и
  замедление (ASM боролся). Заменён.
- **Порт ASM** сделан и сверен построчно с `vendor/nes-disasm/Battle City/bank_FF.asm`
  (sub_DC97, точки A/B, sub_DD6E/DD76, кайма буфера). Подтверждён тестами.
- Важный нюанс реализации: `stepTank` должен передавать в `canLead` ТЕКУЩУЮ
  позицию (не сдвинутую), т.к. `canLead` сам прибавляет `dx/dy` (как ASM считает
  от текущей позиции).
